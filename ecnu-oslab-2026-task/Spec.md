用户地址由页表翻译，内核不能把一个用户虚拟地址当作本机普通指针直接解引用。用户堆自低地址向上，用户栈自高地址向下；二者及 `mmap` 区域都不能相互覆盖。

**正常启动依赖：**`mmap_init()` 必须由启动核在首次使用节点池前且仅初始化一次；本分支常规 `main()` 尚未调用它，实现时需在 `proc_make_first()` 前补入。节点池专项测试已自行初始化；测试后恢复常规启动时也必须保留初始化，不能只在专项测试中可用。

**框架接口更正：**当前骨架把 `uvm_mmap` 在 `mem/method.h` 和 `mem/uvm.c` 中声明为 `void`，但 `sys_mmap` 的既定契约是返回实际映射起始地址，且 `begin==0` 时该地址只能由 `uvm_mmap` 选出。因此实现时允许且应当把两处返回类型同步改为 `uint64`，成功返回最终 `begin`；不要只改一处，也不要让 `sys_mmap` 在自动选址时错误返回 0。

### 2.1 关键接口约定

VA 表示虚拟地址，PTE 表示页表项；`len` 与 `npages` 不是同一个单位。下面列出调用边界，跨页处理和资源维护方法由 D1–D3 解释。

| 接口/对象 | 输入、输出与边界 |
|---|---|
| `uvm_copyin` / `uvm_copyout` | 都接收 `pgtbl, dst, src, len`；`len` 是字节数，地址可能未对齐，也可能跨页；方向以 `uvm.c` 注释为准，二者均返回 `void` |
| `uvm_copyin_str` | 最多复制 `maxlen` 字节，遇到 `\0` 停止；返回 `void`，不能凭空检查其“错误返回值”；上限内未遇终止符时，不保证结果是 C 字符串。调用方如需以 `%s` 使用容量为 `C` 的缓冲区，应保证 `C>=1`，最多复制 `C-1` 字节并在自身容量内置 `buf[C-1]=0`；不得向仅有 `maxlen` 字节的目标缓冲区的 `dst[maxlen]` 越界补写 |
| `sys_mmap` / `uvm_mmap` | 用户测试传入长度是字节，内核映射接口接收页数；须检查页对齐并换算。`begin==0` 表示请求自动选址，不是映射零地址页 |
| `sys_brk` / `uvm_ustack_grow` | 前者成功返回堆顶、失败返回 `-1`，参数 0 表示查询；后者成功返回新的栈页数、失败返回 `(uint64)-1`。缺页地址可能一次跨过多页，合法时应补齐缺页所在页到旧栈底之间的全部页面；不能用 `<0` 检查无符号结果 |
| `vm_unmappages(..., freeit)` | `freeit=true` 释放被解除映射的物理页，不是让它随意删除仍在使用的中间页表；完整页表销毁由 `uvm_destroy_pgtbl` 组织 |
| `uvm_copy_pgtbl` / `uvm_destroy_pgtbl` | 复制接口不复制 trapframe/trampoline，二者由进程初始化准备；给定销毁入口会释放私有 trapframe、仅解除共享 trampoline 的映射，外层不要再次释放同一页 |

**堆的最低边界：**创建进程时，依据实际已装入的代码/数据镜像及其映射保留不可收缩的初始堆顶，后续 `brk` 不得低于它，避免解除代码/数据页；不能只判断地址是否大于 `USER_BASE`。当前 `proc_t` 只有可变的 `heap_top`，允许增加必要的初始堆边界字段（如 `heap_base`），并在创建/回收时初始化或清理；不要在每次查询时从已变化的堆顶重新推断。Lab6 fork 须继承它，后续 exec 须按新镜像重新设置，不要求本实验提前实现 fork/exec。

`uvm_mmap/uvm_munmap` 内部失败按骨架采用 `panic`；系统调用层应对能提前识别的非法参数按其注释返回 `-1`。不要把这两层混为一谈，也不要求把全部内核断言改成可恢复错误。

### 2.2 用户地址空间示意

下面只表示区域顺序，不按实际长度比例绘制；边界值查本分支 `mem/type.h`。

```text
低地址 → 代码/数据及堆（向高处增长）
       → MMAP_BEGIN | mmap 区域 | MMAP_END
       → 栈预留空间（用户栈从 TRAPFRAME 下方向低处增长）
       → TRAPFRAME → TRAMPOLINE → 高地址
```

只实现本分支要求的内存功能；不增加写时复制、换页或文件映射。D3 写清三种资源的关系即可，无需学生写完整链表算法。

### D1：用户数据迁移

**问题：**

1. 分别写出 `copyin`、`copyout` 的源和目的属于用户空间还是内核空间。
2. 解释为何要查用户页表，以及数据跨页时为何不能只翻译第一次地址。
3. 说明字符串长度上限的作用，并给一个方向或边界出错的现象。

**本组决策（学生填写）：**

>  1. `copyin` : src属于用户空间, dst属于内核空间; `copyout` : src属于内核空间, dst属于用户空间.
>  2.  在内核态的时候，satp指向的是内核页表，用户虚拟地址无法在内核页表上查询到正确的物理地址，所以要查用户页表找到正确的用户地址;页表独立映射，虚拟地址连续不一定物理地址也连续，必须每页单独翻译
>  3. 限制从用户地址最多读 maxlen 字节，又限制向内核缓冲最多写 maxlen 字节.防止没有\0一直读下去，或着地址过长超出内核缓冲限制

**边界、失败结果与验证方法（学生填写）：**

> 边界：数据跨页时只翻译第一次地址
> 失败现象：后续的页面会在第一个地址翻译到的物理地址后面连续读取，可能不与后续的虚拟地址对应，因此读入错误的数据

### D3：`mmap` 与用户页表生命周期

**问题：**

1. 新建或解除 mmap 时，用“页表映射、物理页、链表节点”三个栏目列出要维护的资源。
2. 给出一个重叠或越界请求，说明为什么不能接受。
3. 分别说明页表复制要独立复制哪些用户区域、销毁时为何不能释放共享 trampoline。无需写递归代码或所有拆分分支。

**本组决策（学生填写）：**

>  1. 
    | 栏目     | 新建 mmap                                                       | 解除 mmap                                                        |
    |----------|------------------------------------------------------------------|------------------------------------------------------------------|
    | 页表映射 | 为 [begin, begin+npages*PGSIZE) 每页建 PTE_V\|R\|W\|U，指向新物理页 | vm_unmappages(..., freeit=true) 清 [begin, begin+len) 的 PTE      |
    | 物理页   | 从 pmem 分配 npages 页，逐页挂到 PTE                              | freeit=true 释放被解除映射的物理页                                |
    | 链表节点 | mmap_region_alloc 取节点，按 begin 有序插入 p->mmap，相邻用 mmap_merge 合并，被合并节点回收 | 命中区域拆分/裁剪（头/中/尾），释放节点回仓库，中间挖洞可能新申请节点 |
   2. 越界: sys_mmap(MMAP_BEGIN - PGSIZE, 2*PGSIZE) 侵占堆区；sys_mmap(MMAP_END - PGSIZE, 2*PGSIZE) 越过 MMAP_END 侵占栈预留区。mmap 区是 [MMAP_BEGIN, MMAP_END) 的专属区域，越界会覆盖堆/栈的映射、破坏其他区域页表。
   3. 复制（uvm_copy_pgtbl）：用户页表中带 PTE_U 的用户可访问页——代码页、
   数据页、堆页、栈页、mmap 区页——都为子进程分配新物理页、复制内容、建独立映射.不复制 trapframe与 trampoline。
   销毁（uvm_destroy_pgtbl）：释放用户数据页；释放私有 trapframe；
   trampoline 只解除映射.

**边界、失败结果与验证方法（学生填写）：**

> 越界 mmap 若被接受，会覆盖堆/栈已有映射、破坏其他区域页表；重叠 mmap 若被接受，同 VA 两次建 PTE 使先映射物理页丢失引用（泄漏），两节点记同一物理页导致 munmap double free，链表有序性被破坏。
销毁时若 free trampoline，后续进程 ecall 跳 trampoline 访问已释放页崩溃。
  · 复制时若把 trampoline 复制成新物理页（多余）或把 trapframe 共享（错误），
    切换/返回用户态异常。
